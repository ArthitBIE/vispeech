# vispeech — Project Agent Rules

## Stack

- **Next.js 16.2.10** (App Router) + React 19, TypeScript, Tailwind CSS 4, shadcn/ui
- **Package manager: pnpm** (11.x, per `packageManager` field). Never use `npm` or `bun` for installs in this repo.
- **Supabase** backend (auth: email/password + Google OAuth; tables: words, practice_logs, word_accuracy, practice_sessions)
- **Tests**: Vitest (unit, in `src/lib/**/__tests__/`) + Playwright (e2e, in `e2e/`)

## Next.js 16 specifics that apply here

- **`proxy.ts` not `middleware.ts`** — the `middleware` filename/export is deprecated. The file lives at `src/proxy.ts` and exports `proxy(request)`. Proxy runs on the Node runtime (edge is not supported).
- `src/proxy.ts` is an auth gate: it reads the Supabase session cookie and redirects unauthenticated visitors away from protected pages to `/auth/signin`; `/api/*` and `/_next/*` pass through (API routes auth via the `Authorization` header).
- The Next.js 16 docs in `node_modules/next/dist/docs/01-app/` are authoritative — read them before writing Next-specific code.

## Conventions

- **Routing**: authenticated app pages live under `src/app/(app)/` (dashboard, home, settings) and use the AppShell layout. Auth flows live under `src/app/auth/` (signin, signup, callback).
- **Practice flow**: lessons are defined in `src/lib/lesson.ts` (`LESSONS`: คำศัพท์, เสียงสระ, บทสนทนา). Session practice is `src/app/practice/session/page.tsx`; single-word practice is `src/app/practice/[word]/page.tsx`. Sessions complete to `/summary`.
- **TTS**: server route `src/app/api/tts/route.ts` (edge-tts-universal); client helper `src/lib/tts.ts`. Force-dynamic.
- **Scoring**: visual (mouth openness via MediaPipe) + audio (Web Speech transcript) → weighted total, persisted via `POST /api/score` and sessions via `/api/practice-sessions` (GET/POST/PATCH).
- **Supabase clients**: browser client in `src/lib/supabase/client.ts`; server-side API routes create a per-request client with the `Authorization: Bearer <token>` header. Use `.maybeSingle()` (not `.single()`) on queries that may return zero rows to avoid PGRST116 errors.
- **Env**: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (`.env.local`, gitignored). E2E uses `E2E_TEST_EMAIL`/`E2E_TEST_PASSWORD`.
- **Middleware/proxy change**: if you touch `src/proxy.ts`, keep the same matcher. The proxy intentionally enforces auth (see the auth gate note above).

### Playwright E2E — Retry Limit
*~100,000 tokens/session saved*
- `pnpm test:e2e` / `rtk playwright test e2e/practice-session.spec.ts` was re-run 159x in a single session without changing source code — same test kept failing. Rule: after 3 identical failures, STOP re-running. Read the error output, fix root cause in source, then re-run once. Never re-run the same failing e2e test without a code change between runs.

### File Reads — API Routes
*~50,000 tokens/session saved*
- `src/app/api/score/route.ts`, `src/app/api/words/route.ts`, `src/app/api/practice-sessions/route.ts`, `src/app/api/tts/route.ts`, `src/lib/viseme/index.ts`, `src/lib/tts.ts` all consistently fail with `runtime_error` on Read tool across sessions. Use `Bash: cat <file>` or `Bash: rtk read <file>` instead of the Read tool for these files — they appear to have binary/encoding issues that break the Read tool parser.

### RTK Overuse
*~20,000 tokens/session saved*
- Commands like `rtk grep`, `rtk ls`, `rtk find`, `rtk sed`, `rtk cat` are read-only operations — rtk wrapping adds token overhead for trivial commands. Use raw commands for simple read-only operations (ls, grep, find, cat, head, tail). Reserve rtk for commands with verbose output that benefit from compression (git, build, test).

### Port 3000 Conflicts
*~15,000 tokens/session saved*
- E2E runs frequently fail with `http://localhost:3000 is already used`. Before starting e2e tests, always: `lsof -ti :3000 | xargs -r kill -9; sleep 2`. Never start `pnpm dev` manually — Playwright's webServer config handles it.

### codemap Skill
*~5,000 tokens/session saved*
- `skill: {'name': 'codemap'}` consistently fails with `ERROR(unknown)` across 15+ sessions. The skill is registered but broken. Read `codemap.md` files directly or use `Bash: rtk ls <dir>/codemap.md` instead. Do not attempt to invoke the codemap skill.

### DashboardContent.tsx Line Reading
*~3,000 tokens/session saved*
- `sed -n '195,210p' src/components/dashboard/DashboardContent.tsx` was repeated 8x with different line ranges. Use `Read` tool with offset/limit to read the section you need in one call, not repeated `sed` with overlapping ranges.
